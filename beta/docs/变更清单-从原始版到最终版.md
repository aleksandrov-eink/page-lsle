  1. 接通 `anti_fade`，并把「整屏 GC16 重推」改为**全像素 GL16 白推**当前帧：白底吃 GL16 的

  FULL（行周期补到 11090us/帧），每相脉宽回到校准值、中灰按表落点；揭页条带仍加密到最多
  32 带，节拍仍 12ms/拍（帧 11.09ms < 12ms，动画仍约 68 拍 ≈ 0.82s），单次推屏、结束提交
  基准，不追加第二遍定稿。快刷档（8 带 / FAST / 11.09ms）与其它翻页路径不变。

### 1.0q 页屿系统 1.15.0（水波纹·高清抗锯齿加强 + 坚果云进度同步闪退修复）

- 水波纹·高清：揭页引擎条带从 8 带加密到最多 32 带（行分带每带至少 8 行、列分带每带至少

- 修复坚果云「同步阅读进度」闪退（真机必现）：根因是云同步任务只有 8KB 栈，进度同步路径在进入
  TLS 前已用约 5.6KB（新设备探测占用 8×288B 栈数组、合并结果按固定 96 条分配），叠加 HTTPS 握手
  后溢出 panic；并且合并结果行最多可达 192 条（本机 96 + 仅云端 96），旧版超出 96 条会越界写堆。
  修复：任务栈 8192→12288 字节；探测改单缓冲逐个 stat、合并结果按本机+云端实际条数分配并在
  每次追加前校验；apply 下标按合并行数分配。实测同步路径栈占用约 3.3KB→1.3KB；云端文件读回上限同步提升到 192 行，
  避免「写出 192 行、读回 96 行」在下次同步时误删云端条目。

### 1.0p 页屿系统 1.14.1（修复扩展名不符的 PNG/JPEG 无法预览）

- 用户反馈：TF 卡存入的 PNG「有时候无法预览」，透明书封与阅读背景都出现。根因：解码器只按文件
  扩展名选择 PNG/JPEG 解码器，而手机、微信/QQ、下载站保存的文件经常扩展名与实际内容不符（例如
  JPEG 数据存成 `.png`，或 PNG 存成 `.jpg`）；这类文件在透明书封预览报「PNG无法加载」，在阅读
  背景报「图片解码失败（文件可能损坏）」。
- 修复：新增按文件头 magic 识别真实格式（PNG 签名 / JPEG SOI），`book_image_*`、透明书封层解码、
  阅读背景 4bpp 直写全部改为按内容选解码器；JPEG 内容的书封按不透明层处理并照常自动去白；透明
  书封 / 图片页补齐 Adam7 隔行 PNG 解码；PNG CRC 字段损坏或尾部缺失时按已解出的像素继续显示。
